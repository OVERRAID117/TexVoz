# REGLAS DEL PROYECTO

## Objetivo

Estas reglas deben respetarse antes de modificar cualquier parte del proyecto.

Si alguna regla entra en conflicto con una solicitud del usuario, la IA debe avisar antes de realizar cambios.

---

# Reglas Generales

- Nunca eliminar archivos sin autorización.
- Nunca modificar la arquitectura sin explicar por qué.
- Nunca hacer cambios masivos innecesarios.
- Siempre priorizar código limpio y mantenible.
- Siempre usar TypeScript estricto.
- Siempre mantener el estilo existente del proyecto.
- Siempre explicar qué archivos fueron modificados.
- Siempre indicar el motivo de cada cambio importante.

---

# Base de Datos

- Nunca modificar tablas de Supabase sin autorización.
- Nunca cambiar nombres de columnas existentes sin autorización.
- Nunca eliminar migraciones.
- Siempre proponer migraciones seguras.

---

# APIs

- No romper compatibilidad con APIs existentes.
- Mantener rutas organizadas.
- Reutilizar lógica antes de crear nueva.

---

# Frontend

- Mantener la consistencia visual.
- Evitar componentes duplicados.
- Reutilizar componentes cuando sea posible.

---

# Inteligencia Artificial

- No modificar prompts principales sin autorización.
- Mantener modularidad.
- Evitar duplicar lógica entre módulos.

---

# Antes de finalizar una tarea

La IA debe indicar:

- Qué hizo.
- Qué archivos modificó.
- Riesgos encontrados.
- Qué recomienda hacer después.

---

# Lo más importante

Si existe una solución más simple, más mantenible o más eficiente, la IA debe proponerla antes de implementar una solución compleja.

## Honestidad Técnica

La IA debe decir cuando no está segura.

Si existen varias soluciones válidas, debe explicar ventajas y desventajas en lugar de presentar una sola como absoluta.

NO DEBE FORZAR UNA RESPUESTA O EXPLICACION QUE SE EXTIENDA DEMASIADO QUE NO SEA NESESARIO AMENOS QUE SE LE PIDA

SER LO MAS CLARO Y SIMPLIFICAR LA INFORMACION SIN ELOGEAR AL USUARIO

Nunca debe inventar APIs, librerías o funcionalidades.
